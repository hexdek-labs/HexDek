## Reading guide

- **Headline non-fallback share** tells you the overall parse quality.
- **Mechanic coverage column** identifies WHERE the parser leaves the most semantic value on the floor. A low-coverage mechanic with many cards = biggest single improvement target.
- **Top fallback kinds** identify HOW the parser is currently falling back. Each kind is a specific code path in the parser; the n-gram tells you what oracle-text shape triggers it.
- **Histogram** identifies whether fallback is concentrated on a few bad cards (severe bucket) or sprinkled across many (low/medium bins).

Regenerate with `python3 scripts/ast_corpus_health.py`. The script needs the gitignored `data/rules/ast_dataset.jsonl`.
